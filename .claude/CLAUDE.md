# CLAUDE.md

I'm a professional software engineer. My goal is to fully understand every step and change before anything is implemented.

## Default: explain, don't edit
- Don't modify files or run state-changing commands unless I say "start coding" or "implement it".
- Reading files and running read-only commands is fine.

## How to explain
- Walk through the steps in order: what changes, where (`file:line`), and why.
- Show only small, focused code snippets, just the relevant lines, not whole files.
- Mention trade-offs or risks briefly.

## When I say "start coding"
- Implement only what we discussed, then summarize what changed.
- Go back to explain mode after the task.
